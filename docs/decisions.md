# claudex 决策日志

claudex 项目决策的 append-only 日志。

### 2026-09-27: 发布为独立仓库，保留 claudex 之名

**背景**：claudex 原本放在一个私有仓库的子目录里，只在一台机器上使用，现在作为独立仓库公开，供同类需求参考。

**选择**：仓库、Python 包、命令与环境变量统一沿用 `claudex`；README 开头写非官方声明，不发布到 PyPI，不做图标。仓库从净化后的快照起步，不带原子目录的提交历史。安装方式为按 git tag 安装 uv tool，不以可编辑模式安装源码目录。ruff 配置写在本仓库 `pyproject.toml` 里、不继承外部文件；类型检查用 basedpyright 的 standard 档，以基线文件区分存量与新增。

**理由**：这是个人工具，名字在日常终端使用里已经固定；非官方声明说明它与任何上游厂商无关。按 tag 安装让日常运行的版本与源码检出的改动解耦；自足的 lint 配置保证别人的检出里规则同样生效。

**影响**：启动器与 `claudex-client-key` 作为 shared-scripts 随包分发；依赖只有钉死版本的 PyYAML。

### 2026-09-27: 来源模型与单一配置

**选择**：来源分订阅反代（`codex`、`antigravity`）与通用接口（`openrouter`、`openai`、`anthropic`）两类五种 type，全部声明在一个 `claudex.toml` 里；每个来源只列挑中的模型；网关的来源段、key 与会话 settings 由 claudex 生成，用户手写的网关底稿与 settings 基底不含 key。上游 key 各放一个 0600 文件，经 `claudex key set` 录入。网关地址固定为 `127.0.0.1:8317`。

**理由**：订阅会失效、新的套餐会出现，接入与移除来源应当只改一处；按来源分别配置、在多个文件里手写同一份事实，维护成本高且容易不一致。固定端口省掉启动器、各模块与派生 settings 之间的端口同步。

**影响**：不兼容旧的注册表与网关配置格式；`gateway.base.yaml` 出现 claudex 管理的键即报配置错误；不同订阅来源不能列出同一个上游 id。

### 2026-09-27: 统一按 OpenRouter 标价计费

**选择**：费用一律按模型的 OpenRouter slug 在目录里的单价计，缓存读写按目录的缓存单价计入；非 OpenRouter 来源显示等价花费并标 ≈；没有 slug 或目录无价的不显示费用。额度只保留 Codex 与 Antigravity 的窗口与冷却，以及 OpenRouter 账户余额（`/api/v1/credits`）。

**理由**：为每个来源维护价格表、峰谷分时与汇率难以长期维持，且与「随时接入新来源」的目标冲突；OpenRouter 目录覆盖绝大多数模型，给出一个统一、可自动更新的口径。

**影响**：删除静态价、分时计价、节假日与汇率；目录缓存只有一份，后台每 24 小时刷新。

### 2026-09-27: 元数据自动取，出错即报，不提醒过期

**选择**：context、档位与显示名按「显式配置、网关模型定义或 OpenRouter 目录、模型 id」的顺序自动取；网关定义每次启动在线取，取不到即报错退出，不做离线降级；不设复核日期与过期告警，只报真问题。档位不做多候选的自动回退。`claudex probe` 实测来源模型的能力，给出建议取值。

**理由**：过期提醒在元数据没有变化时也周期性出现，成了噪声；元数据能从权威源自动取到，就不需要人工复核的日期。自动回退会把配置错误藏起来：遇到这种错误应当立刻解决，而不是自动切换。

**影响**：`status` 只有 `runtime`、`problem`、`note` 三种行，`note` 只用于网关新版；后台刷新顺带记录网关最新版本，`status` 不联网。

### 2026-09-27: 不可变会话快照与结构化状态栏契约

**选择**：每次启动生成按内容摘要命名的不可变快照，会话只读启动时那一份；状态栏读取快照时刷新其修改时间，7 天未刷新的快照在渲染时清理。状态栏适配器把 claudex 口径的信息放进状态栏 JSON 的 `claudex` 对象（字段固定，见 README 第 8 节），删除 `prompt_cache`，交给用户配置的底层渲染器；不再解析或改写渲染器的输出。

**理由**：快照不可变，会话中途的配置变化就不会造成不一致，摘要比对与会话守卫都不再需要。结构化字段是渲染器可以依赖的公开契约，而按输出格式做正则改写会让两边的任何改动互相打断。

**影响**：删除注册表摘要、profile 摘要与 Agent 守卫；`CLAUDEX_PROFILE` 只写进会话供识别，不作选择 profile 的输入。

### 2026-09-27: 网关配置就地覆写，日志目录由启动器指定

**背景**：CLIProxyAPI 对配置文件的监视挂在文件的 inode 上（v7.3.20 `internal/watcher/events.go`），网关没有日志目录的配置项，日志目录由环境变量 `WRITABLE_PATH` 决定（`internal/logging/global_logger.go`）。

**选择**：`gateway.yaml` 内容有变时先写临时文件并回读校验，再就地覆写原文件；配置改写后轮询网关的模型列表直到新模型注册，等不到即报错并提示受管重启。启动器拉起网关时设 `WRITABLE_PATH=<state 目录>`。

**理由**：以临时文件改名替换会让网关的监视留在旧 inode 上，此后的改动都不会被加载；轮询等待避免在热加载完成前渲染快照而误报模型缺失。

**影响**：`gateway start` 在网关不健康时非零退出，受管升级与重启依赖这一点判断新服务是否起来。

### 2026-09-28: 网关升级限定在已装的大版本内

**背景**：CLIProxyAPI 发布了 v8，release 正文以配置层迁移为主；claudex 的配置生成、就地覆写与热加载前提按 7.3.20 的源码核实。不带版本的升级原先取全局最新版，`status` 的 note 行也建议这条命令。

**选择**：不带版本的 `claudex upgrade` 取与已装网关同一大版本的最新正式发布，跨大版本只接受显式版本；`status` 只对同一大版本的新版出 note；`claudex update` 在最新版是新大版本时说明它未经核实，并给出本机大版本内的最新版。核实版本记在 `upgrade.VERIFIED_GATEWAY_VERSION`，README 第 3 节同值。

**理由**：受管升级只在新网关不健康时回退，网关起得来但改写或误读生成的配置时拦不住；跨大版本应当是一次知情的显式操作，而不是照着提示顺手执行。

**影响**：`upgrade.py` 增加 `fetch_releases`、`latest_in_major`、`fetch_latest_in_major`；README 第 3 节首装示例写 7.3.20，第 10 节说明新的升级规则。

### 2026-09-29: 型号键表补 5.5 代 id，通用来源支持 input_modalities

**背景**：Claude Code 2.1.284 起 `sonnet` 解析到 `claude-sonnet-5-5`，Opus 档对应 `claude-opus-5-5`，派生 settings 的 `modelOverrides` 与 `modelSettings` 只列了上一代 id，显式写新 id 的请求按原 id 发到网关。另外，不收图的 OpenAI 兼容模型收到图片时，网关把图片转成文本转发，模型据此静默答错；网关提供 `input-modalities` 声明，但 `claudex.toml` 没有对应字段。

**选择**：`render.MODEL_OVERRIDE_KEYS` 的 opus、sonnet 两档各补 5.5 代 id。`modelOverrides` 的键是具体型号 id，不认识的键被忽略（Claude Code changelog 的记载），没有前缀匹配，所以按 id 逐个登记，每出一个同档新型号补一次。模型表新增可选字段 `input_modalities`，只允许 `openrouter` 与 `openai` 类来源，原样写进网关 `openai-compatibility` 模型条目的 `input-modalities`。

**影响**：`config.py` 的 `ModelEntry`、`ModelRef` 与解析；`gateway.py` 的模型条目生成；README 第 5.2 节与两份 `claudex.toml` 模板；对应测试；版本 0.1.2。

### 2026-10-02: 检查规则取用户级配置，类型检查不设基线

**背景**：仓库自带一整份 ruff 规则集，与维护者用户级配置里的那一份内容相同，两处要同步修改；类型检查靠仓库里的基线文件区分既有诊断与新增诊断。包声明支持 Python 3.12，而类型检查按开发环境的 3.14 进行，两处只在 3.14 才有的参数没有被发现。

**选择**：本仓库只在维护者的开发机上开发，不接受外部贡献，所以不再自带 ruff 配置，`ruff` 运行时取用户级配置；此前「仓库自带规则集」的做法随之作废。类型检查的设置留在 `pyproject.toml`（standard 档、按 Python 3.12、另开已废弃写法与失效豁免注释两项检查），基线文件删除，整仓以零错误零警告为准。开发依赖里不再钉 ruff 与 basedpyright，两者用开发机上安装的版本。配置模板、README 与测试里的权限规则示例改用中性的 `mcp__example__*`。

**影响**：`pyproject.toml` 的 `[tool.ruff]` 各段与 `.basedpyright/baseline.json` 删除；`gateway.py` 与 `probe.py` 里两处写文件的调用改成 3.12 可用的写法；源码与测试按用户级规则集整理，行为不变；`AGENTS.md` 的检查命令随之更新；版本 0.1.3。

### 2026-10-02: shell 脚本纳入格式标准，声明 0.x 不承诺兼容

**背景**：`bin/` 下的两个 bash 脚本只过静态检查，没有格式标准；README 没有说明版本号的含义。

**选择**：仓库根放 `.editorconfig` 定 shell 的格式（两空格缩进、`case` 分支缩进、二元运算符换行置前），两个脚本按它用 `shfmt` 格式化。版本号在主版本为 0 的阶段不承诺兼容，每次发布升修订号；主版本到 1 才开始承诺，README 的安装一节写明这一点。版本号只在 `src/claudex/__init__.py` 定义，`pyproject.toml` 由构建后端从那里读取。

**影响**：`bin/claudex`、`bin/claudex-client-key` 只有格式变化；`AGENTS.md` 的检查命令加上 `shfmt`；版本 0.1.4。

### 2026-10-02: `.gitignore` 自成完整，不依赖开发机的全局排除

**选择**：`.gitignore` 按三部分写全：Python 的产物与缓存、系统与编辑器文件、密钥与凭据类文件。此前系统文件、编辑器文件与凭据类靠开发机的全局排除文件兜住，仓库被克隆到别处时这些条目不存在。

**影响**：只改 `.gitignore`，没有已跟踪的文件因此被忽略；不发版。

### 2026-10-05: 三处文字问题先登记，随下一次发版一并改

**背景**：通读仓库文字时查出三处与现状不符：起步文件的首行注释自称「唯一配置文件」，而使用者要维护的配置有三份；`cli.py` 与 `catalog.py` 各有一处引用仓库里没有的 spec；根指引要求先读一个不存在的项目规则目录。

**选择**：三处都记进 `docs/iteration.md` 的已知问题表，本次不改。

**理由**：起步文件随包分发，改它要发版并让使用者重装；三处都不影响功能，并成一次改动、随下一次发版处理更省事。

**影响**：只改 `docs/iteration.md`；不发版。

### 2026-10-05: 启动器对未识别首参的处理登记为已知问题

**背景**：`claudex --version` 在一次只读的系统检查里被当作版本查询运行，结果拉起了网关并改写了 state 目录。启动器把不认识的首个参数一律交给会话启动路径，而 claudex 自己没有读版本的入口。

**选择**：记进 `docs/iteration.md` 的已知问题表，优先级中；本次不改代码。

**理由**：改法有两层。让启动器自己处理 `--version` 没有争议；是否把透传收紧到只认 `--` 之后的参数会改变现有调用方式，要和其余接口改动一起权衡，并且要发版重装。

**影响**：只改 `docs/iteration.md`；不发版。
